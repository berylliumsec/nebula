## Persistence and migration

Bookmarks, queues, decisions and read cursors use additive kinds in the existing versioned entity store. No SQL DDL migration or model-generated backfill is required. Optional fields on messages, turns and request snapshots preserve old records. Managed records are excluded from generic CRUD; workflow routes enforce scope, provenance and expected revisions. Conversation deletion cascades conversation-owned records; project decisions remain project-owned. Queue recovery never silently replays ambiguous delivery.

Before deployment, retain an online SQLite backup and the old live commit/bundle identity. Rolling back code does not erase additive records, but an old Core cannot drain the new queue. Pause queues before an intentional rollback; preserve linked turn records and review uncertain delivery before retrying.
