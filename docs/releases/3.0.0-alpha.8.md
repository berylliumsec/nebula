# Nebula 3.0.0-alpha.8

Nebula 3.0.0-alpha.8 supersedes the unpublished alpha.6 and alpha.7
candidates. It refines Nebula into a calmer security workstation while making
harness-driven investigations, mobile access, and durable Missions more
coherent and recoverable.

## Changes since alpha.5

- The Workbench, project surfaces, Settings, Diagnostics, dialogs, and mobile
  navigation now share one responsive visual system across conventional,
  Zero, light, dark, system, and high-contrast themes.
- Assistant conversations prioritize the transcript and required operator
  actions. Routine harness telemetry is collapsed, while commentary, tool
  calls, approvals, failures, interruptions, and recovery actions remain
  visible.
- Grok ACP and Codex harness sessions expose supported model, effort, and
  execution controls without surfacing vendor protocol noise in the primary
  activity feed.
- Selected context preserves exact UTF-8 bytes across SHA-256 validation, and
  quoted context is compact and expandable in chat.
- LAN browser access has an explicit pairing lifecycle with device-local
  session recovery, clearer credential failures, and responsive iPhone-sized
  layouts.
- Terminal, Code, Browser, Files, Notes, Missions, and Activity use consistent
  toolbars and capability-aware browser fallbacks.
- Missions support durable sequential stages, scheduling and recurrence across
  restarts, explicit retry lineage, URL-selected state, and reviewed promotion
  into Findings or Reports.
- Workspace folders are resolved consistently across host files, code,
  terminals, and harness working directories.
- A permanent visual and interaction audit now covers representative desktop,
  compact, narrow, mobile Chromium, and mobile WebKit states.
- Linux managed packages retain the signed APT installation path introduced
  after alpha.5.

This candidate adds the harness and mobile-foundation database migration. The
migration is forward-only and preserves existing engagement records.

## Native packages

The release workflow stages the following artifacts for manual review:

- a Linux x86_64 AppImage for direct distribution; and
- a Linux x86_64 DEB for managed distribution.

Direct builds can consume Nebula's signed updater channel. Managed builds omit
the direct updater so deployment remains under administrator control. macOS,
Windows, Linux arm64, RPM, Flatpak, Snap, and Homebrew artifacts are not
included in this alpha.

The packaged desktop includes the Chromium runtime required for rendered URL
sources. Docker or Podman is still required for terminal and automation
features. A model provider or supported assistant harness is optional; the
human terminal, evidence workflow, notes, findings, and reports remain usable
without one.

## Alpha limitations

- This is a prerelease and may contain compatibility defects or incomplete UX.
- Engagement bundle export is integrity-manifested, but this alpha does not yet
  provide a bundle restore path.
- Terminal and automation availability depends on a compatible local container
  runtime and its networking configuration.
- Local providers and assistant harnesses vary in capability. Nebula enables
  structured tools only after the selected runtime passes its verification
  contract.
- Physical iPhone Safari remains a manual release-verification gate; automated
  mobile WebKit coverage does not replace it.

## After installation

Launch the desktop with `nebula`. Confirm the bundled Core, browser runtime,
and local execution boundary before beginning an engagement:

```console
nebula-core doctor --json
```

Report defects with the exact version, platform, failed action, correlation
ID, and a Diagnostics support bundle after reviewing it for sensitive
engagement data.
