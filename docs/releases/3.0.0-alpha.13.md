# Nebula 3.0.0-alpha.13

Nebula 3.0.0-alpha.13 advances the Linux desktop prerelease with a persistent
Assistant workspace, managed browser control, clearer project runtime choices,
and more durable mobile and reconnect behavior.

## Changes since alpha.12

- Assistant conversations now provide persistent navigation, bookmarks,
  editable branches, queued follow-ups, explicit decisions with provenance,
  inspectable context and retained results, durable catch-up, and compact
  activity that distinguishes an idle harness from active work.
- The managed browser is integrated with Assistant conversations. Operators can
  load pages, keep browser control active until stopped, inspect compact page
  previews, and reach browser settings without losing the working context.
- Project execution now exposes explicit Host and Docker modes. Grok sessions
  retain the selected project workspace across restart, and supervised host
  sessions remain bounded by their project scope.
- Project creation and host-folder browsing now support paginated folder
  discovery and navigate directly into the new Assistant workspace. Projects
  can be removed and restored, including from the iPhone deployment surface,
  with archive failures reported in interface diagnostics.
- Provider setup includes OrcaRouter as a named OpenAI-compatible option. Saved
  project profiles retain their selected VPN, and terminal public-IP status is
  visible from the top bar.
- Secret Service discovery no longer stalls Core health checks when the desktop
  keyring is unavailable, and desktop crash diagnostics avoid false orphan
  failures.
- Browser and application actions use compact, accessible icon controls with
  tooltips, while mobile composer focus and settings anchoring remain stable.
- Default Assistant execution and artifact-query caps were removed. Operators
  remain responsible for stopping work and browser control when their task is
  complete.

## Native packages

The release workflow stages a Linux x86_64 AppImage for direct distribution and
a Linux x86_64 DEB for managed distribution. macOS, Windows, Linux arm64, RPM,
Flatpak, Snap, Homebrew, and browser extensions are not included in this alpha.

The packaged desktop includes the Chromium runtime required for rendered URL
sources and managed Assistant browsing. Docker or Podman is required for
container execution, terminal, automation, VPN, and isolated debugger features.

## Deliberate boundaries and alpha limitations

- This is a prerelease and may contain compatibility defects or incomplete UX.
- Host mode runs authorized agent commands on the Nebula host; Docker mode keeps
  execution inside the configured container boundary. Select the mode deliberately.
- Managed browser control can act on authenticated web sessions. Review the
  visible page and stop browser control when it is no longer required.
- VPN routing applies to selected container workloads, not to the Nebula host or
  the browser device used to operate Nebula remotely.
- The protected release workflow does not build a macOS package.
- Physical iPhone Safari, physical macOS remote-Core, provider-diverse, and
  authenticated-browser workflows remain manual verification gates.

## After installation

Launch the Linux desktop with `nebula`, then verify the bundled Core:

```console
nebula-core doctor --json
```

Create or select a project, choose Host or Docker execution deliberately, and
open Assistant. Browser control is available from the Assistant workspace when
the managed browser runtime is healthy.

Report defects with the exact version, platform, failed action, correlation ID,
and a reviewed Diagnostics support bundle.
