# Nebula 3.0.0-alpha.14

Nebula 3.0.0-alpha.14 advances the Linux desktop prerelease with an
assistant-owned application model, more reliable project and conversation
recovery, simpler knowledge access, and clearer execution boundaries.

## Changes since alpha.13

- The Assistant now owns a durable application knowledge graph for project
  resources, relationships, workflow state, and provenance. Operators can use
  this context without a separate model-management interface.
- Loaded project and Library sources are available to Assistant conversations
  automatically when the selected runtime permits project data, and the
  knowledge gateway starts enabled before the first source is added. Installed
  harness skills remain available independently of the Nebula knowledge gateway.
- Assistant conversations recover more reliably across reloads, reconnects,
  long histories, queued follow-ups, approvals, and mission progress. Resource
  retries and configured harness defaults now restore authoritative Core state.
- The integrated browser keeps page control with the Assistant while presenting
  operators with a quieter, read-only page viewer and durable browser context.
- Approved source runs use a disposable, non-root container with unrestricted
  outbound bridge networking while retaining exact-source review, signed
  preflight, workspace isolation, limits, and project policy prohibitions.
- Host-folder selection supports debounced filtering across paginated results,
  and message actions use compact accessible controls with touch-sized mobile
  targets.
- Release and pull-request validation now use diff-bound focused test receipts.
  Full suites require separate explicit approval and are no longer started as a
  release shortcut.

## Native packages

The release workflow stages a Linux x86_64 AppImage for direct distribution and
a Linux x86_64 DEB for managed distribution. macOS, Windows, Linux arm64, RPM,
Flatpak, Snap, Homebrew, and browser extensions are not included in this alpha.

The packaged desktop includes the Chromium runtime required for rendered URL
sources and managed Assistant browsing. Docker or Podman is required for
container execution, terminal, automation, VPN, and isolated debugger features.

## Deliberate boundaries and alpha limitations

- This is a prerelease and may contain compatibility defects or incomplete UX.
- Host mode runs authorized agent commands on the Nebula host; Docker mode keeps
  execution inside the configured container boundary. Select the mode
  deliberately.
- Managed browser control can act on authenticated web sessions. Review the
  visible page and stop browser control when it is no longer required.
- VPN routing applies to selected container workloads, not to the Nebula host or
  the browser device used to operate Nebula remotely.
- The protected release workflow does not build a macOS package.
- Physical iPhone Safari, physical macOS remote-Core, provider-diverse, and
  authenticated-browser workflows remain manual verification gates.

## After installation

Launch the Linux desktop with `nebula`, then verify the bundled Core:

```console
nebula-core doctor --json
```

Create or select a project, choose Host or Docker execution deliberately, and
open Assistant. Project and Library sources are available automatically when
the selected runtime permits project data.

Report defects with the exact version, platform, failed action, correlation ID,
and a reviewed Diagnostics support bundle.
