# Nebula 3.0.0-alpha.21

Nebula 3.0.0-alpha.21 is the next Linux desktop prerelease after the unpublished
alpha.20 candidate. It includes the changes merged into `main` through
`a31328c` (September 25, 2026).

## Changes since alpha.20

- Assistant conversations now have more durable turn, tool-result, and activity
  records, with recovery work for interrupted turns, paused goals, subagents,
  and external harness sessions.
- The conversation workbench has clearer progress, queue position, tool
  activity, and subagent views. Transcript and session controls include search,
  archive, editing, copying, and more reliable switching and reconnect behavior.
- Provider and harness work adds OpenRouter model discovery and routing fixes,
  retry and error handling, reasoning display, native command hooks, and
  project-scoped subagent communication.
- Phone and desktop layouts receive navigation, settings, editor, terminal,
  browser, and accessibility improvements. The linked project workspace and
  server-owned session state receive additional lifecycle and recovery fixes.
- Browser, MCP, automation, Mission, diagnostics, and execution boundaries
  receive correctness, security, and resource-use fixes.

These are release highlights, not a complete list of the commits since
alpha.20. The [source comparison](https://github.com/berylliumsec/nebula/compare/nebula-v3.0.0-alpha.20...nebula-v3.0.0-alpha.21)
contains the full change history.

## Native packages

The protected release workflow produces a Linux x86_64 AppImage for direct
distribution and a Linux x86_64 DEB for managed distribution. It does not build
macOS, Windows, Linux arm64, RPM, Flatpak, Snap, Homebrew, or browser-extension
artifacts.

The packaged desktop includes the Chromium runtime used for rendered URL
sources and managed Assistant browsing. Docker or Podman is required for
container execution, terminal, automation, VPN, and isolated debugger features.

## Alpha limitations

- This prerelease may contain compatibility defects or incomplete workflows.
- Host mode runs authorized agent commands on the Nebula host; Docker mode uses
  the configured container boundary. Select the execution mode deliberately.
- Managed browser control can act on authenticated web sessions. Review the
  visible page and stop browser control when it is no longer required.
- VPN routing applies to selected container workloads, not the Nebula host or
  the remote browser device.
- Physical iPhone Safari, physical macOS remote-Core, provider-diverse, and
  authenticated-browser workflows remain manual verification gates.

## After installation

Launch the Linux desktop with `nebula`, then verify the bundled Core:

```console
nebula-core doctor --json
```

Create or select a project, choose Host or Docker execution, and open Assistant.
Report defects with the exact version, platform, failed action, correlation ID,
and a reviewed Diagnostics support bundle.
