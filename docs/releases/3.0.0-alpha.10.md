# Nebula 3.0.0-alpha.10

Nebula 3.0.0-alpha.10 adds project-scoped autonomous web testing and lets a
desktop UI shell use a selected remote Nebula Core while keeping native browser,
proxy, identity, and credential execution on that desktop.

## Changes since alpha.9

- Project Browser sessions now own a long-lived native interception proxy shared
  by their tabs. Project CAs are created atomically, expose certificate status,
  fingerprint, expiry, rotation, revocation, and trust guidance, and never expose
  private keys or silently alter the operating-system trust store.
- Browser traffic supports bounded HTTP/1.1, HTTP/2, HTTPS, and WebSocket capture,
  declarative pass, block, redirect, delay, header, body, and frame rules, replay,
  redacted body artifacts, and HTTP, HTTPS CONNECT, and SOCKS5 upstream proxies.
  Scope, mutation limits, TLS validation, and upstream failures remain
  fail-closed.
- Missions can request an operator-approved browser autonomy lease tied to the
  current Project scope revision, desktop device, identity, target subset, risk
  classes, credential references, expiry, and budgets. Durable commands, rules,
  receipts, events, and Evidence survive refresh and reconnect and can be stopped
  through the existing run lifecycle.
- The AI browser tool surface can observe, navigate, interact, extract, replay,
  capture Evidence, inspect and configure the proxy, and emergency-stop a run.
  It cannot execute arbitrary JavaScript or read cookies, storage, passwords, or
  tokens. Credential material remains in the paired desktop's operating-system
  vault and enters Core only as a reference.
- Terminal readiness now reports oversized Project workspaces before attempting
  startup and gives the operator a recovery path to choose a smaller authoritative
  Project root. It does not raise the existing 50,000-entry safety limit or create
  a hidden terminal-only workspace.
- Desktop settings can select the supervised local Core or an authenticated
  remote HTTP(S) Core. Remote mode does not launch a local sidecar: the shell uses
  the selected Core's API and WebSockets while native Browser/proxy work continues
  locally under a stable desktop-device identity.
- Remote Core setup now validates authenticated health through native desktop
  networking before saving the token. HTTP requires explicit acknowledgement,
  HTTPS certificate errors fail closed, and timeout, token rejection, TLS, and
  HTTP status failures receive distinct recovery messages.
- Assistant follow-up messages can be queued while a response is active, and
  mission resource budgets default to unlimited when the operator does not set a
  bound.

This candidate adds a database migration for browser-automation indexes. Existing
Projects, conversations, Evidence, Findings, Reports, browser research state, and
workspace data are preserved.

## Native packages

The release workflow stages the following artifacts for manual review:

- a Linux x86_64 AppImage for direct distribution; and
- a Linux x86_64 DEB for managed distribution.

Direct builds can consume Nebula's signed updater channel. Managed builds omit
the direct updater so deployment remains under administrator control. macOS,
Windows, Linux arm64, RPM, Flatpak, Snap, Homebrew, and browser extensions are not
included in this alpha.

The packaged desktop includes the Chromium runtime required for rendered URL
sources. Docker or Podman is required for terminal, automation, and isolated
debugger features. A model provider or supported assistant harness remains
optional.

## Deliberate boundaries and alpha limitations

- This is a prerelease and may contain compatibility defects or incomplete UX.
- Autonomous web testing remains constrained to the operator-approved Project
  scope, identity, lease, risk classes, and budgets. Exploitation, persistence,
  destructive actions, and scope changes require a separate durable step-up grant.
- TLS interception requires the operator to trust the displayed Project CA.
  Nebula does not silently install trust, bypass certificate validation, or expose
  the CA private key.
- The visible native webview is the browser identity and execution plane. This
  release does not add a second Playwright/headless identity store, arbitrary
  JavaScript execution, cookie or token extraction, pixel screenshots, or an
  extension marketplace.
- Remote Core mode does not move browser secrets or native webview execution to
  Core. Mobile and ordinary web clients may monitor and stop runs but cannot claim
  native browser commands.
- The protected release workflow does not build a macOS package. A macOS desktop
  build must be produced and verified through a separate supported distribution
  process before macOS availability is claimed.
- Physical iPhone Safari and physical macOS remote-Core workflows remain manual
  verification gates; automated WebKit and macOS CI do not replace them.

## After installation

Launch the Linux desktop with `nebula`, then verify the bundled Core and local
execution boundary:

```console
nebula-core doctor --json
```

Report defects with the exact version, platform, failed action, correlation ID,
and a Diagnostics support bundle after reviewing it for sensitive engagement
data.
