# Nebula 3.0.0-alpha.18

Nebula 3.0.0-alpha.18 advances the Linux desktop prerelease with a more focused
Coding workspace, durable Assistant and external-harness sessions, concurrent
Ask Nebula conversations, and clearer execution and browser boundaries.

## Highlights

- Ask Nebula now supports disposable side conversations that can be moved,
  hidden, restored, and used concurrently without taking over the primary chat.
  Temporary Ask Nebula harnesses remain tool-free, and stalled popup setup can
  recover without leaving an unusable session behind.
- Codex and Grok sessions reconnect more reliably, retain their names and
  reasoning, and expose trustworthy connection state. Queued follow-ups no
  longer remain visible after dispatch, and loaded conversations stay pinned to
  their final message while Core refreshes.
- Coding gives the operator's work more space with a focused Workbench header,
  compact terminal and secondary controls, a resizable editor sidebar, and
  mobile access to contextual actions.
- Harness thoughts and inline commentary render as readable Markdown, while
  approvals, failures, and other actionable items remain visible.
- Host execution preserves the selected harness's native tools. Host mode runs
  authorized commands on the Nebula host; Docker mode retains the configured
  container boundary.
- The integrated browser clears stale macOS proxy state before direct
  navigation, reports native-browser scope more accurately, and surfaces a
  restart notice when recovery requires one. Security Browser interception now
  remains associated with the intended workspace.
- Terminal opens alongside Assistant, selected output can be attached to a
  conversation, and durable shell code fences can run in the active terminal.
- Assistant project and Library sources remain available automatically when the
  selected runtime permits project data. Conversation, project, resource,
  approval, and mission state recover from authoritative Core data across
  reloads and reconnects.
- Release and pull-request validation use diff-bound focused test receipts. Full
  suites require separate explicit approval and are not started as a release
  shortcut.

## Native packages

The release workflow stages a Linux x86_64 AppImage for direct distribution and
a Linux x86_64 DEB for managed distribution. macOS, Windows, Linux arm64, RPM,
Flatpak, Snap, Homebrew, and browser extensions are not included in this alpha.

The packaged desktop includes the Chromium runtime required for rendered URL
sources and managed Assistant browsing. Docker or Podman is required for
container execution, terminal, automation, VPN, and isolated debugger features.

## Deliberate boundaries and alpha limitations

- This is a prerelease and may contain compatibility defects or incomplete UX.
- Host mode runs authorized agent commands on the Nebula host; Docker mode keeps
  execution inside the configured container boundary. Select the mode
  deliberately.
- Managed browser control can act on authenticated web sessions. Review the
  visible page and stop browser control when it is no longer required.
- VPN routing applies to selected container workloads, not to the Nebula host or
  the browser device used to operate Nebula remotely.
- The protected release workflow does not build a macOS package.
- Physical iPhone Safari, physical macOS remote-Core, provider-diverse, and
  authenticated-browser workflows remain manual verification gates.

## After installation

Launch the Linux desktop with `nebula`, then verify the bundled Core:

```console
nebula-core doctor --json
```

Create or select a project, choose Host or Docker execution deliberately, and
open Assistant. Project and Library sources are available automatically when
the selected runtime permits project data.

Report defects with the exact version, platform, failed action, correlation ID,
and a reviewed Diagnostics support bundle.
