# Scope-policy Unicode and compatibility provenance

`static_data.json` is generated by
`scripts/capture_assistant_scope_policy.py` under CPython 3.12 with Unicode
15.0.0. Its Nameprep normalization data comes from
`unicodedata.ucd_3_2_0`; its character classification and lowercase-dependent
mapping results use the explicitly captured Python runtime. The generator calls
`stringprep` and `unicodedata` APIs to compute character mappings, canonical
combining classes/compositions, prohibited/bidirectional ranges, printable
classification, NFKC delimiter mappings and decimal-digit observations. It does
not read or copy CPython source text into the generated tables. These computed
Unicode data are accompanied by the unchanged `LICENSE-UNICODE.txt` notice in
this crate.

The Rust compatibility code was handwritten with CPython 3.12's
`encodings/idna.py`, `urllib/parse.py`, and `ipaddress.py` as behavioral references,
and with Nebula's `ScopePolicy` and `MissionGrant` validators as the application
contract. It preserves source validation order, protocol error strings and
normalization results. It does not embed the Python implementations or launch a
Python helper. This source consultation is distinct from the provenance of the
generated Unicode data; the algorithms are not represented as originating solely
from Unicode tables.

Nameprep normalization is implemented against the captured Unicode 3.2 data;
the pinned Rust `idna` dependency is used only for Punycode encoding. Modern
IDNA/UTS46 policy is not substituted for the legacy codec. The source oracle
compares the complete generated tables and the retained validation/privacy
vectors so that runtime or Unicode drift remains visible.
