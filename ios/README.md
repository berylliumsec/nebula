# Nebula for iPhone

Private UIKit/WKWebView shell for your existing Nebula server. iOS 17 or later.
Persistent WebKit storage retains web pairing. Native settings save only the server
address. Chats, tools, permissions, and session state remain in Nebula Core.

## Build on the Mac

Use Xcode 27 on macOS 27. Install XcodeGen with `brew install xcodegen`, then:

```sh
xcodegen generate
open Nebula.xcodeproj
```

Select the Nebula target, Signing & Capabilities, and your development team.
Choose the attached iPhone and Run. Developer Mode must be enabled on the phone.
A free Personal Team can require periodic rebuilding when its profile expires.

The first launch shows a native Connect screen; the suggested WireGuard address
(`http://10.10.0.2:8000`) is editable, and every address that loads is remembered
(most recent first, up to three) as one-tap chips. Allow local network access and
complete Nebula's web pairing. HTTP is unencrypted; use it only on your trusted LAN
or VPN. The app keeps normal TLS validation. External HTTP(S) links require
confirmation and open in a Safari sheet.

The selected server address is saved as soon as Connect is tapped, so an app restart
or temporary network failure returns to that address. The recent-server chips and
last-connected time update only after a page loads successfully.

With native build 4 or later, the web view runs edge to edge with no native bar.
The installed app opens the Core-backed assistant: project conversations, the composer, saved
results, and pending chat approvals or agent questions. Terminal, Missions,
Activity, and other Workbench tools stay in full Nebula on desktop or mobile web.
Build 5 adds the microphone permission description for Nebula Voice. The Core UI
also exposes the Nebula assistant and Voice from this shell. Voice needs a trusted
HTTPS server address; HTTP LAN addresses continue to support text chat and show
an in-place HTTPS recovery message if Voice is started.
The page's `theme-color` controls the status bar. Native UI appears only for:

- **Connect** — first launch, or App connection in the conversation drawer,
  which opens `nebula://settings` (server address, pairing link, reload).
- **Offline** — a failed page load explains what failed and offers Try again,
  the other saved address, or Change server; the web view stays underneath.

The page is told it runs in the shell only through the user-agent token
`NebulaShell/1.0`; there is still no script bridge.

## Verification

```sh
xcrun swiftc Nebula/ServerAddress.swift Tests/main.swift -o /tmp/nebula-address-tests
/tmp/nebula-address-tests
xcodebuild -project Nebula.xcodeproj -scheme Nebula -configuration Release \
  -sdk iphoneos -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
```

App source and unsigned build are not physical-device acceptance. See QUALITY.md
for required pairing, chat, reconnect, keyboard, rotation, and browser evidence.
Web downloads, external authentication redirects, and permission-dependent media
workflows have not yet been validated in this shell.

## Pairing

Tap Pair to paste the link generated by Nebula's host-side Paired devices settings.
The link must belong to the server selected in the app. Confirm the matching code
in the web form and tap Pair device. Native deep links use
`nebula://pair?url=<percent-encoded Nebula pairing URL>` and open that same form;
they never automatically grant authorization.
